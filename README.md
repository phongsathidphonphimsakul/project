# ลานรถ

เว็บแอปสำหรับเต็นท์รถมือสอง: ลงรถ จดค่าใช้จ่ายทุกรายการ แล้วคำนวณราคาขายจากกำไรที่ต้องการ
ใช้ React + Vite + TypeScript และเก็บข้อมูลบน **Supabase** (Auth, Postgres, Storage)

## ทำอะไรได้บ้าง

**ต้นทุนและราคา**
- ลงรถ (ยี่ห้อ รุ่น ปี ทะเบียน เลขตัวถัง เลขไมล์ ราคาซื้อ ซื้อจากใคร) พร้อมเลขสต็อกอัตโนมัติ และเตือนทะเบียน/เลขตัวถังซ้ำ
- จดค่าใช้จ่ายแยกหมวด (ซ่อมเครื่อง ทำสี ยาง ค่าโอน ค่านายหน้า ฯลฯ) กดหมวดเป็นปุ่มลัด พิมพ์ `3.5k` ได้ จำชื่อร้าน/ช่างที่เคยใช้
- สรุปทุนรวม และกราฟแท่งแยกหมวดว่าเงินไปหมดที่ไหน
- ตั้งราคาได้ 3 แบบ: **กำไรเป็นบาท**, **% จากทุน** (markup), **% จากราคาขาย** (margin)
- บวก "เผื่อลูกค้าต่อราคา" และปัดราคาขึ้น (ลงท้าย 9,000 / หมื่น / 5 พัน / พัน) ได้ทั้งราคาตั้งขายและราคาต่ำสุดที่ยอมได้
- ช่อง "ลูกค้าต่อราคา" ใส่ราคาที่ลูกค้าขอ แล้วบอกทันทีว่ายังกำไรเท่าไหร่ / ต่ำกว่าเป้า / ขาดทุน
- ค่างวดไฟแนนซ์แบบดอกเบี้ยคงที่ (ดาวน์ %, ดอกเบี้ย/ปี, รวม VAT 7%) หลายระยะเวลา

**การขาย**
- สถานะรถ: เพิ่งซื้อเข้า → กำลังเตรียมรถ → พร้อมขาย → ติดจอง (ชื่อ เบอร์ มัดจำ) → ขายแล้ว (ราคาขายจริง ผู้ซื้อ)
- กำไรจริงและจำนวนวันที่ใช้ขาย
- พิมพ์ป้ายราคาติดกระจกรถขนาด A4 (ราคา + ดาวน์ + ค่างวด + ชื่อ/เบอร์เต็นท์)

**ทีม (ใช้ร่วมกันทั้งเต็นท์)**
- เจ้าของเชิญพนักงานด้วยอีเมล พนักงานสมัคร/เข้าสู่ระบบด้วยอีเมลนั้นแล้วกดเข้าร่วม
- บทบาท **เจ้าของ** กับ **พนักงาน**: พนักงานลงรถ ลงค่าใช้จ่าย ตั้งราคา จอง/ขายได้ แต่ลบรถ แก้การตั้งค่าเต็นท์ และจัดการทีมไม่ได้ ลบค่าใช้จ่ายได้เฉพาะรายการที่ตัวเองลง
- เห็นการแก้ไขของคนอื่นทันที (Supabase Realtime) และรู้ว่าใครลงค่าใช้จ่ายรายการไหน ใครแก้รถล่าสุด
- เลขสต็อกออกโดยฐานข้อมูล ลงรถพร้อมกันหลายคนเลขไม่ซ้ำ
- อยู่ได้หลายเต็นท์ (เช่น หลายสาขา) และสลับเต็นท์ได้
- สิทธิ์ทั้งหมดบังคับที่ฐานข้อมูลด้วย Row Level Security ไม่ได้ซ่อนแค่ปุ่มบนหน้าจอ

**ใช้บนมือถือ**
- ติดตั้งลงหน้าจอโฮมได้ (PWA): Android กด "ติดตั้งแอป" ในหน้าตั้งค่า, iPhone เปิดใน Safari → แชร์ → เพิ่มไปยังหน้าจอโฮม
- เปิดเต็มจอเหมือนแอป มีเมนูล่าง ถ่ายรูปรถจากกล้องได้ เปิดแอปได้เร็วเพราะแคชตัวแอปไว้ (ข้อมูลรถดึงจาก Supabase เสมอ)
- ต้อง deploy เป็น https ก่อน มือถือถึงจะติดตั้งได้

**ภาพรวมและเครื่องมือ**
- ภาพรวม: รถในเต็นท์, เงินทุนจมในสต็อก, กำไรที่รออยู่, กำไรเดือนนี้, กราฟกำไร 6 เดือน
- รายการ "ต้องจัดการ": รถจอดนานเกินกำหนด และรถที่ยังไม่ตั้งราคา
- **ประเมินก่อนซื้อ**: ใส่ราคาที่คาดว่าขายได้ + ค่าซ่อมที่ต้องใส่ → บอกว่าควรซื้อเข้าไม่เกินเท่าไหร่
- ค้นหา/กรอง/เรียงรายการรถ, ถ่ายรูปรถจากมือถือ (ย่อขนาดก่อนอัปโหลด)
- ส่งออก CSV (เปิดใน Excel ภาษาไทยไม่เพี้ยน), สำรอง/นำเข้า JSON
- ใช้บนมือถือได้ (เมนูล่าง), รองรับโหมดมืด

## ติดตั้ง

1. สร้างโปรเจกต์ที่ [supabase.com](https://supabase.com/dashboard)
2. เปิด **SQL Editor** แล้วรันไฟล์ใน `supabase/migrations/` ตามลำดับ
   - `20261006000000_init.sql` — ตารางรถ ค่าใช้จ่าย และ bucket รูป `car-photos`
   - `20261007000000_teams.sql` — ระบบทีม (เต็นท์ สมาชิก คำเชิญ), สิทธิ์ RLS, เลขสต็อกอัตโนมัติ, Realtime
     ถ้าเคยใช้เวอร์ชันก่อนแล้ว ข้อมูลเดิมของแต่ละบัญชีจะถูกย้ายเข้าเต็นท์ของบัญชีนั้นให้อัตโนมัติ
   หรือถ้าใช้ Supabase CLI: `supabase link` แล้ว `supabase db push`
3. คัดลอก `.env.example` เป็น `.env.local` แล้วใส่ `VITE_SUPABASE_URL` และ `VITE_SUPABASE_ANON_KEY` (Project Settings → API)
4. ถ้าต้องการให้สมัครแล้วใช้ได้ทันทีไม่ต้องยืนยันอีเมล: Authentication → Sign In / Providers → ปิด *Confirm email*
5. รัน

```bash
npm install
npm run dev      # เปิด http://localhost:5173
npm test         # ทดสอบสูตรคำนวณ
npm run test:db  # ทดสอบ migration และสิทธิ์ทีม (RLS) บน Postgres จำลอง
npm run build    # ได้ไฟล์ใน dist/ เอาไปวางบน Vercel / Netlify / Cloudflare Pages ได้เลย
```

ตอน deploy อย่าลืมตั้ง environment variable สองตัวข้างบน และเพิ่ม URL ของเว็บใน Supabase → Authentication → URL Configuration

## สูตรที่ใช้

| | สูตร |
|---|---|
| ทุนรวม | ราคาซื้อ + ค่าใช้จ่ายทุกรายการ |
| กำไรเป็นบาท | ราคาต่ำสุด = ทุน + กำไร |
| % จากทุน | ราคาต่ำสุด = ทุน × (1 + %) |
| % จากราคาขาย | ราคาต่ำสุด = ทุน ÷ (1 − %) |
| ราคาตั้งขาย | ราคาต่ำสุด + เผื่อต่อราคา แล้วปัดขึ้น |
| ค่างวด | (ยอดจัด + ยอดจัด × ดอกเบี้ย/ปี × ปี) ÷ งวด × 1.07 ถ้ารวม VAT |
| ซื้อเข้าได้ไม่เกิน | ราคาที่คาดว่าขายได้ − กำไรที่ต้องการ − ค่าใช้จ่ายที่ต้องใส่ |

ตัวอย่าง: ทุน 300,000 อยากได้ 15% → *% จากทุน* ได้ราคา 345,000 (กำไร 45,000) แต่ *% จากราคาขาย* ได้ 352,942 (กำไร 52,942)

## โครงสร้าง

```
src/lib/calc.ts       สูตรคำนวณทั้งหมด (มี unit test)
src/lib/store.ts      สถานะแอป + ซิงก์กับ Supabase (อัปเดตหน้าจอก่อน แล้วค่อยบันทึก) + ทีม + realtime
src/lib/pwa.ts        ติดตั้งเป็นแอปบนมือถือ (public/sw.js, public/manifest.webmanifest)
src/lib/supabase.ts   Supabase client
src/pages/            หน้าจอแต่ละหน้า
supabase/migrations/  โครงสร้างฐานข้อมูลและ RLS
```

## กันโปรเจกต์ Supabase (แพ็กเกจฟรี) ถูกพัก

แพ็กเกจฟรีจะพักโปรเจกต์ถ้าไม่มีการใช้งานประมาณ 1 สัปดาห์ `.github/workflows/supabase-keep-alive.yml` จะส่งคำขอเล็กๆ ไปที่ฐานข้อมูลทุก 3 วัน

1. GitHub repo → **Settings → Secrets and variables → Actions → New repository secret** เพิ่ม
   `SUPABASE_URL` และ `SUPABASE_ANON_KEY` (ค่าเดียวกับที่ใส่ใน Vercel)
2. ไฟล์ workflow ต้องอยู่ใน branch หลัก (`main`) GitHub ถึงจะรันตามเวลา
3. ทดสอบ: แท็บ **Actions → Supabase keep-alive → Run workflow** ต้องขึ้นเครื่องหมายถูกสีเขียว
   ถ้ารันไม่ผ่าน GitHub จะส่งอีเมลแจ้ง
